01 — Features

Six non-negotiables,
zero exceptions.

Each constraint is enforced in code and tested. Violating one is a build failure, not a style choice.

C-05

Deterministic confidence

Confidence is computed by deterministic post-processing. LLMs never self-report a score — they can only suggest global weight changes through calibration.

C-08

Token economics

Every model and tool call is metered. Per-run budgets, per-finding caps, and degradation signals drop optional specialists before security.

C-09

Audit or it didn't happen

Append-only audit log. Every finding, routing decision, and approval action carries a SHA-256 checksum. No soft deletes, no updates, no exceptions.

LLM

Enrichment, not verdicts

New in v0.5.0: the LLM Gateway enriches findings with explanations, unified-diff fixes, and CWE-mapped risk — asynchronously, batched by concern type.

GATE

Approval queue

Sub-threshold findings never auto-post. Human review with SLA escalation, dual-secret rotation, and delivery-ID replay protection.

MCP

9-tool MCP server

Wire Verdity into Claude Desktop, Cursor, or any MCP client: four review specialists, full review, enforcement, rules, and LLM enrichment.

02 — Pipeline

Webhook to verdict
in five moves.

Ingestion decoupled from processing. Specialists fan out in parallel. The router decides. Nothing posts without a gate.

1

Ingest

GitHub webhook → constant-time HMAC-SHA256 verify → durable event queue, partitioned by repo.

Orchestrate

Scatter-gather fan-out to four specialist agents — timeout-isolated, one failure never blocks the rest.

3

Aggregate & score

Deterministic dedup, conflict resolution, and multi-signal confidence scoring. This is where a finding earns its number.

Route

Auto-approve above 0.9, manual review below, dismiss under 0.6. Sub-threshold findings wait in the approval queue — never posted.

Post & audit

04 — Architecture

Nine constraints.
One audit trail.

01
HMAC before parse. Constant-time SHA-256 verification on the raw body. No bypass path exists.
02
Queue-decoupled. Ingestion only publishes; processing is a separate durable stage.
03
Parallel, isolated. Specialists run concurrently under individual timeouts.
04
One semantic index. Shared embeddings and symbol graph — no private stores per agent.
05
Deterministic confidence. Computed by code, never by an LLM self-report.
06
Gated fixes. Compile → lint → no-new-secrets → independent verifier, in order.
07
Approval gate. Sub-threshold findings queue for humans. Always.
08
Metered calls. Every model invocation goes through TokenEconomicsService.
09
Audited everything. Findings, decisions, approvals — checksummed and append-only.

05 — Install

Verdict in five minutes.

Install

Python 3.11+. One dependency pull, no native build steps.

$ pip install verdity==0.5.0

Configure

GitHub App credentials via environment — never committed.

$ cp .env.example .env
# WEBHOOK_HMAC_SECRET, GITHUB_APP_ID,
# GITHUB_APP_INSTALLATION_ID, GITHUB_APP_PRIVATE_KEY

Run the gateway

FastAPI ingestion, stateless, sub-second responses.

$ uvicorn verdity.gateway.app:app --port 8000

Review a PR

CLI, MCP, or webhook — same deterministic pipeline.

$ verdity-review run --owner acme --repo widgets --pr 42
.verdity.yml — LLM enrichment (optional) 
llm:
  enabled: true
  default_model: "qwen2.5-7b-instruct"
  default_backend: "ollama"   # local-first, always
  ollama_url: "http://localhost:11434"

  enrichment:
    enabled: true
    default_mode: "explain"   # explain | fix | risk | all
    batch_size: 10
    async: true              # never blocks the review

  calibration_assist:
    enabled: true
    trigger_on_drift: true
    min_samples: 20

The LLM never touches finding.confidence at runtime. It enriches context and suggests weight changes — the router stays deterministic.
